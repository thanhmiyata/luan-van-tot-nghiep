# Multi-Agent NL2SQL System with CrewAI

This project implements a Natural Language to SQL (NL2SQL) conversion system using CrewAI's multi-agent approach. The system takes natural language questions and database schemas as input and generates corresponding SQL queries.

## Overview

The NL2SQL system uses a multi-agent approach with CrewAI to convert natural language questions into SQL queries. The system processes questions from the Spider dataset, a large-scale, cross-domain semantic parsing and text-to-SQL dataset.

The workflow consists of:
1. Selecting the relevant schema for the question
2. Generating SQL based on the question and schema
3. Validating and correcting the generated SQL
4. Saving the results to a CSV file
5. Converting the results to the format required for evaluation

## Project Structure

- `src/nl2sql_flow/main.py`: Main entry point for the NL2SQL system
- `src/nl2sql_flow/crews/nl2sql_crew/config/agents.yaml`: Configuration for the agents used in the system
- `src/nl2sql_flow/crews/nl2sql_crew/config/tasks.yaml`: Configuration for the tasks assigned to each agent
- `convert-output-format.py`: Script to convert the output CSV to the format required for evaluation
- `convert-spider-questions.py`: Script to convert Spider dataset questions to the format required by the system
- `questions.json`: Filtered list of questions from the Spider dataset
- `tables.json`: Database schema information for the Spider dataset
- `train_spider.json`: Original Spider dataset questions
- `gold.sql`: Ground truth SQL queries (generated by convert-output-format.py)
- `predict.sql`: SQL queries generated by the system (generated by convert-output-format.py)

## Installation

### 1. Download the Spider Dataset

Download the Spider dataset from [Google Drive](https://drive.google.com/file/d/1403EGqzIDoHMdQF4c9Bkyl7dZLZ5Wt6J/view) and extract it. Copy the `database` directory to the `test-suite-sql-eval` directory.

### 2. Install CrewAI

```bash
uv tool install crewai
```

### 3. Install Required Libraries

```bash
crewai install
```

### 4. Configure API Keys

Create a `.env` file in the project root with your API keys:

```bash
# Copy the example file
cp .env.example .env

# Edit .env file and add your API keys
GOOGLE_API_KEY=your_google_api_key_here
GEMINI_API_KEY=your_google_api_key_here  # Can be same as GOOGLE_API_KEY
```

**Note**: All agents now use Gemini 2.0 Flash, so you only need a Google API key with Gemini access.

## Usage

### Running the NL2SQL System

To run the system on the questions in `questions.json`:

```bash
crewai run
```

This will process the questions and generate SQL queries, saving the results to a CSV file in the `output` directory.

### Converting Output Format

After running the system, update the output filename in `convert-output-format.py` to match the generated CSV file, then run:

```bash
python3 convert-output-format.py
```

This will generate two files:
- `gold.sql`: Ground truth SQL queries
- `predict.sql`: SQL queries generated by the system

## System Architecture

The system uses three different agents, all powered by Gemini 2.0 Flash for consistency and optimal performance:

1. **Schema Selector** (Gemini 2.0 Flash)
   - Analyzes the natural language question and database schema
   - Filters out irrelevant tables, columns, and keys
   - Produces a simplified JSON schema containing only components relevant to the question

2. **SQL Expert** (Gemini 2.0 Flash)
   - Generates SQL queries based on the natural language question and filtered schema
   - Returns the SQL query as a single line with no line breaks

3. **SQL Validator** (Gemini 2.0 Flash)
   - Validates the syntax, logic, and structure of the generated SQL query
   - Fixes errors if detected
   - Provides an explanation of what the SQL query does
   - Returns an error message if the query cannot be fixed

The multi-agent approach with unified Gemini 2.0 Flash model ensures consistent performance, reduced latency, and cost-effectiveness while maintaining high accuracy in SQL generation.

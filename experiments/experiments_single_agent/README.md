# Single Agent NL2SQL System with CrewAI

This project implements a Natural Language to SQL (NL2SQL) conversion system using a **single agent approach** with CrewAI. The system takes natural language questions and database schemas as input and generates corresponding SQL queries in one comprehensive step.

## Overview

The NL2SQL system uses a **single comprehensive agent** to convert natural language questions into SQL queries. The system processes questions from the Spider dataset and performs all three steps (schema selection, SQL generation, and validation) in one API call.

The workflow consists of:
1. **Single Agent Processing**: One agent handles schema filtering, SQL generation, and validation
2. **Comprehensive Output**: Returns SQL query, explanation, error handling, and filtered schema
3. **Efficient Processing**: Reduces API calls from 3 to 1 per question

## Project Structure

- `src/nl2sql_single_agent/main.py`: Main entry point for the NL2SQL system
- `src/nl2sql_single_agent/crews/nl2sql_crew/config/agents.yaml`: Configuration for the single agent
- `src/nl2sql_single_agent/crews/nl2sql_crew/config/tasks.yaml`: Configuration for the comprehensive task
- `convert-output-format.py`: Script to convert the output CSV to the format required for evaluation
- `questions.json`: Filtered list of questions from the Spider dataset
- `tables.json`: Database schema information for the Spider dataset
- `train_spider.json`: Original Spider dataset questions

## Installation

### 1. Download the Spider Dataset

Download the Spider dataset from [Google Drive](https://drive.google.com/file/d/1403EGqzIDoHMdQF4c9Bkyl7dZLZ5Wt6J/view) and extract it. Copy the `database` directory to the `test-suite-sql-eval` directory.

### 2. Install CrewAI

```bash
uv tool install crewai
```

### 3. Install Required Libraries

```bash
crewai install
```

### 4. Configure API Keys

Create a `.env` file in the project root with your API keys:

```bash
# Create .env file and add your API keys
GOOGLE_API_KEY=your_google_api_key_here
GEMINI_API_KEY=your_google_api_key_here  # Can be same as GOOGLE_API_KEY
```

**Note**: The single agent uses Gemini 2.0 Flash, so you only need a Google API key with Gemini access.

## Usage

### Running the NL2SQL System

To run the system on the questions in `questions.json`:

```bash
crewai run
```

This will process the questions and generate SQL queries, saving the results to a CSV file in the `output` directory.

### Converting Output Format

After running the system, update the output filename in `convert-output-format.py` to match the generated CSV file, then run:

```bash
python3 convert-output-format.py
```

This will generate two files:
- `gold.sql`: Ground truth SQL queries
- `predict.sql`: SQL queries generated by the system

## Evaluation

To evaluate the generated SQL queries, navigate to the `test-suite-sql-eval` directory and run:

```bash
python evaluation.py --gold ../experiments_single_agent/gold.sql --pred ../experiments_single_agent/predict.sql --db database --etype all --table tables.json --plug_value
```

## System Architecture

The system uses **one comprehensive agent** powered by Gemini 2.0 Flash:

### **Single Agent** (Gemini 2.0 Flash)
- **Role**: Comprehensive Natural Language to SQL Converter
- **Responsibilities**:
  - **Schema Selection**: Filter database schema to keep only relevant tables and columns
  - **SQL Generation**: Generate SQL query based on filtered schema and natural language question
  - **SQL Validation**: Validate and fix syntax or logical errors in the generated SQL
- **Output**: Complete result including SQL, explanation, error handling, and filtered schema

## Comparison with Multi-Agent Approach

### **Single Agent Advantages:**
- **Reduced API Calls**: 1 call instead of 3 calls per question
- **Lower Latency**: Faster processing due to fewer API round trips
- **Simplified Architecture**: Easier to maintain and debug
- **Cost Effective**: Lower API costs due to fewer calls

### **Single Agent Disadvantages:**
- **Less Specialization**: Cannot leverage different LLM strengths for different tasks
- **Complex Prompt**: More complex prompt engineering required
- **Harder Debugging**: Difficult to identify which step failed
- **Less Modular**: Cannot easily modify individual steps

### **Performance Comparison:**
- **Multi-Agent**: 3 API calls, specialized LLMs, modular design
- **Single Agent**: 1 API call, comprehensive LLM, simplified design

## Key Differences from Multi-Agent Version

1. **Single Agent**: Uses one agent instead of three specialized agents
2. **Comprehensive Task**: One task handles all three steps (schema selection, SQL generation, validation)
3. **Unified Output**: Returns all information in one response
4. **Simplified Flow**: Single step processing instead of sequential steps

This approach provides a good baseline for comparing performance, cost, and complexity with the multi-agent approach.
